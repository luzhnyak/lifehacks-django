# Результат рев'ю — 10 листопада 2026

## Виправлення запуску через Supervisor

Після винесення секретів у середовище лише SSH-скрипт завантажував `.env`.
Окремий процес Gunicorn, запущений Supervisor, не отримував ці змінні.
Додано автоматичне читання `.env` із кореня проєкту через `python-dotenv`.
Змінні середовища процесу зберігають пріоритет. Регресійні тести перевіряють
запуск production без shell-export та пріоритет налаштувань процесу.
Фактична причина серверного `spawn error` потребує підтвердження stderr-логом.

## Локальна перевірка

Python 3.12.8 / Django 5.2.19, окреме середовище `.venv`:
19 тестів пройшли з `-W error`, `check` не виявив проблем,
`makemigrations --check --dry-run` не виявив змін,
`pip check` не виявив конфліктів. `collectstatic` зібрав ресурси сайту й адмінки,
медіафайли до результату не потрапили. Production checks мають лише два
попередження HSTS, пояснені нижче. Ці перевірки не замінюють серверний запуск.

## Виправлено

- Прибрано повторне оголошення Category, яке спричиняло повторну реєстрацію моделі.
- SECRET_KEY вилучено з коду; production вимагає секрет і дозволені хости.
  DEBUG вимкнений за замовчуванням, параметри HTTPS залежать від середовища.
- Django оновлено з непідтримуваної 5.1 до 5.2.19 LTS; супутні залежності оновлено.
- Неіснуючі дописи повертають 404; посилання категорій працюють;
  усі посилання пагінації зберігають фільтри. Порядок дописів стабільний:
  спочатку новіші, за однакового часу — більший первинний ключ.
- Генератор slug обмежує довжину із суфіксом і обробляє назви без літер/цифр.
  Наявні slug не змінюються при редагуванні заголовків.
- Головна завантажує по чотири дописи категорії двома SQL-запитами,
  без зростання кількості запитів пропорційно кількості категорій.
- Зображення обробляються перед збереженням нових завантажень, через storage API,
  із корекцією EXIF-орієнтації. Звичайне редагування не перезаписує JPEG повторно.
- HTML дописів очищується перед виведенням, а анонси не містять HTML-тегів.
- Виправлено мову документа, домен пошуку, порожні заголовки списку й шлях JS.
- Статика, результат collectstatic і медіа розділені; додано відсутню міграцію
  поля Post.image та зміни порядку сортування.
- CI перевіряє тести, залежності, Django checks, міграції та збір статики
  до запуску наявного SSH-деплою. Деплой використовує перевірений SHA коміту,
  пропускає застарілі push після появи новішого коміту main, застосовує міграції
  та збирає статику.
- Production `check --deploy` залишає W005 і W021: поширення HSTS на всі
  піддомени та preload вимагають підтвердженої готовності домену до HTTPS.
  Ці попередження не приховувалися.

## Межі перевірки та наступні кроки

- Локальні дані та файли користувача не мігрувалися й не переміщувалися.
  Зміни на сервері не виконувалися; налаштування nginx, TLS, резервування та
  перезапуск сервісу потрібно перевірити у серверному середовищі за README.
- Історична міграція 0002 видаляє старий ForeignKey без перенесення зв'язків.
  Вже застосовані міграції не переписувалися; перед оновленням дуже старої БД
  потрібен окремий план збереження зв'язків.
- Одночасне створення однойменних об'єктів може завершитися IntegrityError
  через гонку генерації slug; унікальність захищена БД. Автоматичні повторні
  спроби не додавалися без підтвердженого сценарію конкурентного запису.
- bulk_create та QuerySet.update не запускають model.save; імпортери мають
  враховувати генерацію slug і обробку зображень.
- Локальні перевірки виконуються на Windows/Python 3.12; SSH-deploy,
  Linux/Gunicorn та сам GitHub Actions потребують запуску у відповідному середовищі.
